I'd be careful about attributing salaries to programming languages. People there are rarely paid for knowing a language, They're paid for solving expensive business problems.

C++ salaries are often high because many C++ roles sit in performance-critical systems where latency has direct monetary value. In HFT/ULL, you're paid not for writing C++, but for understanding cache lines, NUMA, lock-free, kernel bypass networking - that is, how code behaves on real hardware.

But not all banking C++ is HFT. A huge amount is risk engines, pricing libraries, market data systems, middleware, security infrastructure, and legacy core platforms.

The same applies to Python. It's used for quantitative research, derivatives modeling, risk analytics, machine learning, portfolio optimization, and data processing. A Math PhD building pricing models in Python can easily outearn a generic C++ developer maintaining messaging or database connectors.

A more accurate conclusion is:

C++ is not the highest-paid language in investment banking. Some of the highest-paid banking roles happen to use C++. Compensation comes from domain expertise and business impact, not from the programming language itself.
