Another misleading headline. Nobody is rejecting Linux kernel patches simply because an LLM was involved.

The actual message on the mailing list is much more specific:

> "If you think your LLM-found/fixed issue in a drivers/staging/ file is really valid, it's fine to submit it BUT you must have first tested it on the actual hardware for the driver."

And:

> "You MUST be willing to defend your submission and prove that it really is correct in fixing a bug that a user can actually hit."

That is not an "AI ban." It is basic engineering accountability: test the patch on real hardware, understand what you are submitting, and be able to justify that it fixes a real problem.

Which is, frankly, exactly what should be expected regardless of whether the patch was written by hand, suggested by an LLM, or delivered on stone tablets.

But "Linux maintainers require contributors to validate AI-assisted patches" is not nearly as emotionally profitable a headline as "Linux rejects AI code."
